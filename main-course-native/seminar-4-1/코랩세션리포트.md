# 코랩 세션 리포트 · AI 기반 UI/UX 디자인 시안 제작

**미션:** 프롬프트로 UI 화면을 만들어 프로토타입까지 완성합니다.

- 화면 이미지: 프롬프트로 생성
- 글자 수정: 이미지 안의 깨진 글자
- 프로토타입: 화면을 배치해 서로 이어지게 구성

코랩 세션에서 조원과 서로의 결과물을 확인하며 작성하는 리포트입니다. 코랩 세션 전에 작성할 부분과 코랩 세션에서 작성할 부분이 나뉩니다.

- 코랩 세션 전 작성(사전 과제)
	- 2장
	- 3-1 표
- 코랩 세션에서 작성
	- 3장부터 6장까지(3-1 표 제외). 위에서부터 차례로 채우며 조원과 이야기합니다. 4-3 마지막 행은 5장을 마친 뒤 작성합니다.

## 1장. 개요

각자 만든 화면 시안을 공유하며, 화면이 **어떻게 구성됐는지** 같이 살펴봅니다.

AI에게 작업을 지시하면 AI는 요청한 내용을 바탕으로 결과물을 만들어 냅니다. 하지만 어떤 화면이 필요하고 화면이 어떤 순서로 이어질지는 사람이 결정해야 합니다. 시안을 완성하고도 어떤 구성이 왜 그렇게 되었는지 이해하지 못하는 부분이 남을 수 있습니다. 따라서 화면의 구성을 직접 확인하고, 세부 내용을 조원들과 함께 살펴봅니다.

**서로 모르는 부분과 놓친 부분을 이야기하고 공유할수록 얻어 가는 것이 많아집니다.** 각자의 경험과 생각을 나누는 과정에서 미처 발견하지 못했던 문제를 알아차리고, 새로운 해결 방법을 찾을 수 있습니다.

## 2장. 작업 정리

2장은 토론에 앞서 각자 작성해 오는 사전 과제입니다. 코랩 세션에 참여하기 전까지 내용을 작성하고, 이를 바탕으로 3장에서 조원들과 바로 토론을 시작할 수 있도록 준비합니다.

### 2-1. 내 결과물 정리하기

코랩 세션을 진행하기 위해 스스로의 작업 결과를 정리합니다. 내 작업 과정을 되짚어 볼 수 있고, 정리한 내용은 조원에게 설명할 때도 도움이 됩니다. 아래 표를 코랩 세션 전에 작성합니다.

| 항목 | 내용 |
|---|---|
| 한 줄 소개 | |
| 조원이 접속할 수 있는 프로토타입 주소 | |
| 작업 로그(작업로그.md)에 적은 프롬프트 수정 단계 (초안 → 수정 → 최종) | |
| 작업 로그를 작성하며 편했던 것 | |

개발자도 작업을 진행하면서 어떤 부분을 변경했는지 기록합니다. 파일의 변경 내용을 저장하는 단위를 **커밋(commit)**이라고 합니다. 커밋에는 보통 무엇을 변경했는지 알 수 있도록 간단한 메시지를 남깁니다.

내 작업 로그에서 한 항목을 선택해, 무엇을 바꿨고 왜 바꿨는지 드러나는 커밋 메시지로 다시 작성합니다.

예를 들어 '버튼 색 수정' 대신 **'로그인 버튼의 글자가 잘 보이도록 배경색을 진한 파란색으로 변경'**처럼 작성할 수 있습니다.

| 항목 | 내용 |
|---|---|
| 작업 로그에서 선택한 항목 | |
| 커밋 메시지로 다시 작성한 문장 | |

코랩 세션에 오기 전에 조원이 접속할 수 있는지 점검합니다.

- [ ] 프로토타입 주소에 조원이 접속할 수 있는지 확인했다

지금 상태를 되짚어 보고 하나를 선택합니다.

- [ ] 생각한 대로 됐다
- [ ] 되기는 했지만 마음에 들지 않는 부분이 있다
- [ ] 일부만 됐다

### 2-3. AI 대화 기록

AI와 작업한 기록을 바탕으로 내가 요청하지 않은 결과와 이해하지 못한 결과를 체크합니다. AI 도구의 대화 이력이나 작업 로그에서 찾고, 남아 있지 않으면 기억나는 대로 적습니다. 이 내용을 바탕으로 3장에서 조원들과 토론을 합니다.

아래 목록에 해당하는 부분을 체크해, 3장 전에 3-1 표에 미리 작성합니다.

- [ ] 내가 요청한 것보다 AI가 더 많이 생성한 부분
- [ ] AI가 왜 이렇게 했는지 파악이 되지 않는 부분
- [ ] 여러 번 다시 요청해야 원하는 결과가 나온 부분
- [ ] 이전 버전으로 돌아가고 싶었던 부분

## 3장. 지시와 구성 대조

요청한 것과 AI가 생성한 것을 비교하면 내가 정하지 않았는데 AI가 대신 정한 부분이 드러납니다. 이 장에서는 미리 작성한 3-1 표로 그 차이를 확인하고 조원과 이야기합니다.

### 진행 방법

1. **살펴보기**
	3-1 표에 미리 작성한 내용을 공유합니다. 내가 작성한 지시문과 AI가 생성한 결과를 비교합니다.
2. **이야기 나누기**
	내가 요청한 것은 어디까지였고, AI는 거기에 무엇을 추가하여 구현했는지 살펴봅니다.
3. **수정한 부분 살펴보기**
	수정한 부분이 있으면 무엇을 왜 수정했는지, 수정한 뒤 무엇이 달라졌는지 서로 이야기합니다.
4. **커밋 메시지 서로 읽기**
	2-1 에서 다시 작성한 커밋 메시지를 조원과 바꿔 읽고 어느 메시지가 더 이해하기 쉬운지 선택합니다.

## 4장. 구성 분석

화면 시안의 구성을 읽을 수 있어야 AI가 생성한 것을 그대로 사용할지 고칠지 판단할 수 있습니다. 코랩 세션에서는 내가 지시한 화면 시안 구성이 정말 내 뜻대로 됐는지, 내가 구성한 화면 시안이 다른 조원에게는 어떻게 보이는지 함께 파악합니다. 이 장에서는 조원의 화면 시안을 함께 읽고, 내 결과물의 안전을 점검합니다.

### 진행 방법

1. **살펴보기**
	조원이 가져온 디자인 도구의 프레임 목록과 이미지 파일 이름을 살펴봅니다. 화면 전환 흐름도 함께 확인하며 각 화면이 어떻게 연결되는지 파악합니다.
2. **이야기 나누기**
	화면과 파일이 왜 이런 구조로 나뉘어 있는지, 다른 방식으로 구성할 수도 있었는지 이야기합니다.

진행이 어렵다면 아래 순서로 확인합니다.
1. 이름을 보고 어떤 역할을 하는 화면인지 추측합니다.
2. 실제 화면을 확인해 예상한 내용과 비교합니다.
3. 이해하기 어려운 부분은 AI에게 "이 화면은 왜 필요한지 설명해 줘"라고 질문합니다.

### 4-1. 구성 요소

구성 요소마다 하는 일과 배치한 이유를 알아야 조원의 결과물을 이해하고 내 결과물도 고칠 수 있습니다. 이번 활동에서는 각 구성 요소가 하는 일과 그렇게 배치한 이유를 작성합니다.

### 4-2. 화면 구성과 설계 의도

구성한 이유를 서로 묻고 답하면 내 결과물에서 설명하지 못하는 부분과 조원의 다른 방식이 드러납니다.

아래 질문은 예시입니다. 참고하거나 내 결과물에 맞게 질문을 새로 만들어, 조원과 자유롭게 묻고 답합니다. 내 결과물이나 조원 결과물에 맞지 않는 질문은 건너뛰어도 되며, 코랩 세션에서 조원과 나눈 질문과 답을 표에 작성합니다.

- 화면을 어떻게 나누었고, 그렇게 나눈 이유는 무엇인가
- 같은 정보가 여러 화면에 나타나는 곳이 있다면, 그렇게 한 이유는 무엇인가
- 화면 전환은 어떻게 연결했는가. 이전 화면으로 돌아가는 연결을 두었다면 어떻게 했는가
- 색상과 글꼴은 어떻게 관리했고, 그렇게 한 이유는 무엇인가
- 화면의 순서를 바꾸면 무엇이 달라질까

### 4-3. 안전 점검

AI 도구를 활용해 만든 결과물은 완성도뿐만 아니라 출처와 사용 조건, 수정이 필요한 부분까지 확인하는 것이 중요합니다. 특히 같은 과제를 수행하더라도 사용한 도구와 작업 방식에 따라 확인해야 할 사항이 달라질 수 있습니다. 이번 활동에서는 자신의 결과물을 점검하고, 조원들과 점검 과정과 판단 기준을 비교하며 놓친 부분이 없는지 살펴봅니다.

|---|---|

## 5장. 조원 작업 비교

같은 과제를 다르게 푼 방법을 비교하면 내 방법의 장단점이 보여 다음 작업에서 사용할 방법을 선택할 수 있습니다. 이 장에서는 조원의 화면 시안과 내 것을 비교하고 적용해 볼 점을 작성합니다.

### 진행 방법

1. **살펴보기**
	조원의 시안을 살펴보며 자신이 만든 화면과 비슷한 역할을 하는 화면을 찾아봅니다.
2. **이야기 나누기**
	비슷한 결과물이라도 화면 구성이나 제작 방식은 다를 수 있습니다. 어떤 차이가 있고, 그 차이가 이후 작업에 어떤 영향을 줄지 이야기합니다.
3. **도구 비교하기**
	사용한 이미지 생성 도구와 디자인 도구를 조원과 비교합니다. 도구마다 편했던 점과 어려웠던 점, 조원의 도구로 바꾸면 달라질 점을 이야기하고, 5-1 표에 한 행으로 작성합니다.

결과물이 달라도 제작 과정에서 비슷한 문제를 겪었을 수 있습니다. 이야기를 시작하기 어렵다면 다음 항목을 비교합니다.

- **이미지 속 글자가 깨졌을 때 어떻게 해결했나요?**
	- 인페인팅을 사용했는지, 직접 수정했는지 비교합니다.
- **여러 화면의 스타일을 어떻게 일관되게 유지했나요?**
	- 시드를 고정했는지, 기존 이미지를 레퍼런스로 활용했는지 비교합니다.
- **화면 사이의 전환 흐름을 어떻게 연결했나요?**
	- 전환 흐름을 연결한 방식을 비교합니다.
